# pricing-migration-reconciler

Small tool I wrote to compare the pricing waterfall of an old SAP ECC 4.7 system against S/4HANA
after a migration. It gives you one Excel with only the rows that don't match, plus a guess at why.

The data in this repo is fake (generated by the `seed` command). I built something like this at a
previous job but I don't have that code anymore, so this is a rebuild from scratch. The condition
types and the waterfall are simplified.

## Why

After moving pricing from ECC to S/4, a condition record that got dropped, shortened, re-dated, or
loaded in another currency or unit changes the net price. Checking thousands of customer/material
combinations by hand is slow and you miss things.

## What it does

1. Reads both databases (SQL Server in real use, SQLite for the demo and tests)
2. Applies a cut-off date, only records changed before it count
3. Maps ECC keys to S/4 keys (customer -> business partner, 18 char material -> 40 char)
4. Resolves the condition records for each row (most specific key first, validity dates, scales)
5. Calculates the waterfall with `Decimal` on both sides
6. Marks each row `PERFECT`, `ROUNDING` (every step within 0.01) or `MISMATCH`
7. Gives each bad row a cause from a fixed set of rules, R01 to R10 (see `docs/causes_reference.md`)
8. Writes the Excel, a JSON summary and a log

## Try it

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
pricing-reconciler seed --as-of 2026-10-18
pricing-reconciler check
pricing-reconciler run --cutoff 2026-10-18
```

The default seed gives 3,000 rows and 66 of them are flagged (6 rounding, 60 mismatch). Those are the
ones I planted on purpose, they're listed in `demo/planted_differences.csv` and one of the tests
checks that the tool finds exactly those.

For SQL Server: `pip install -e ".[mssql]"`, install ODBC Driver 18, and set `RECON_ECC_URL` and
`RECON_S4_URL` in `.env`.

## Running it daily on Windows

```powershell
.\scripts\register_task.ps1 -At "05:00"
```

It uses yesterday as the cut-off, takes a lock so two runs can't overlap, and deletes old outputs.
Exit codes: 0 ok, 1 error, 2 differences found (with `--fail-on-mismatch`), 3 another run active.
More in `docs/scheduling_windows.md`.

## Config

- `config/settings.yaml` database env var names, tables, tolerance, rounding, output
- `config/waterfall.yaml` the waterfall steps and access sequences
- `config/causes.yaml` text and action for each cause

Passwords never go in these files, only the names of env variables.

## Tests

```bash
pytest
```

- No condition exclusion, group or header conditions, custom formulas
- Tests only run on SQLite. The SQL Server, Docker and PowerShell parts are not tested here
